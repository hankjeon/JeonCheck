# 01. 요구사항 및 기능 명세

## 목적과 적용 범위

임베디드 C 코드의 결함과 MISRA 일부 규칙 위반을 찾고, 분석 범위와 진단을 한글로 검토하는 Windows 10/11 x64용 .NET 10 WPF 도구입니다. 아래 기능은 현재 구현을 기준으로 하며, 충족되지 않은 기대 동작은 마지막 절에 구분합니다. MISRA 전체 준수 판정이나 실제 컴파일러·타겟에서의 검증을 대체하지 않습니다.

## FR-01. 소스 임포트와 대상/참조 구분

- 폴더와 개별 파일을 검사 대상 또는 비대상/참조 트리에 추가합니다. 폴더 스캔 확장자는 `.c`, `.h`, `.cpp`, `.hpp`입니다.
- 체크박스가 아니라 두 트리 사이의 이동 버튼으로 검사 대상을 변경합니다. 하위 항목 제거·이동 이력은 프로젝트에 저장됩니다.
- `.c`/`.cpp`를 우선 입력하고, 어떤 소스 dump에도 나타나지 않은 대상 `.h`/`.hpp`는 추가로 직접 분석합니다. 소스가 없으면 대상 헤더를 직접 입력합니다.
- 참조 트리는 포함 경로와 헤더 탐색에 사용합니다. `-i`로 파싱을 막는 방식은 아니며, 포함된 참조 코드는 파싱될 수 있습니다. 결함의 보고 위치를 대상 파일 집합으로 제한합니다.
- C++ 확장자도 임포트되지만 Clang-Tidy에는 `-xc`가 전달되므로 C++ 분석 전체 지원을 의미하지 않습니다.

## FR-02. 타겟 프리셋과 분석 옵션

- 타겟별 Cppcheck 플랫폼 XML과 매크로를 적용하며 크로스 컴파일러 설치는 요구하지 않습니다.
- 현재 선택 가능한 프리셋은 11개입니다: TI C6746/C6655/C6672/C6678 EABI, TI C6746/C6678 COFF, NXP T1024 32/64비트 Big Endian, PolarFire RV64, Versal AP A72, Versal RP R5F.
- C89/C99/C11/C17, 사용자 정의 매크로, `--force`, Clang-Tidy 사용 여부를 선택합니다. 매크로 입력은 쉼표·세미콜론·공백으로 나눕니다.
- `--force`는 Cppcheck의 전처리 설정 조합 검사 옵션입니다. Clang-Tidy의 모든 조건부 분기를 검사하도록 만드는 옵션은 아닙니다.
- TI의 Clang-Tidy 트리플은 ARM 대체 모델입니다. 특히 COFF 40비트 `long`은 Cppcheck와 Clang-Tidy 사이에서 동일한 모델로 보장되지 않습니다.

## FR-03. 불완전한 환경과 노트

- 누락된 헤더가 있어도 가능한 범위를 분석하며 `missingInclude`/`missingIncludeSystem`을 노트로 분리합니다. 라이브러리 모델을 실제 헤더의 완전한 대체로 설명하지 않습니다.
- Clang-Tidy는 검색 가능한 일부 누락 헤더에 빈 stub을 생성합니다. 누락 타입·매크로로 인한 오류까지 해결하는 기능은 아니며 분석 완료를 보장하지 않습니다.
- 분석 범위 제한, 단독 헤더 분석, 비정상 종료, dump 미생성·파싱 실패 등을 노트로 알립니다. Cppcheck 결과 XML 자체를 해석할 수 없으면 분석 오류로 처리합니다.
- 모든 구문 오류나 매크로 오류가 자동으로 노트로 분류되는 것은 아닙니다.

## FR-04. 코드 뷰어와 라인 상태

- 읽기 전용 코드 뷰어에서 파일·줄 번호·인라인 규칙 배지·툴팁을 표시합니다.
- 라인 상태는 현재 필터 결과의 결함, 예외, dump 토큰 기반 분석 상태에 따라 정해집니다. 오류가 포함된 줄은 빨간색, 그 외 결함 줄은 경고 색상입니다.
- 같은 줄의 여러 진단은 `[첫 규칙ID +추가 개수]`로 표시하며 툴팁에 모두 나열합니다. 대표 규칙은 가장 심각한 항목을 우선하도록 보장되지 않습니다.
- 토큰이 존재한다는 표시는 모든 규칙 검사가 성공했다는 보장이 아닙니다. 여러 전처리 설정의 분석 줄은 합집합으로 병합합니다.

## FR-05. 분석 엔진과 한글 해설

- Cppcheck 기본 검사, C#의 dump 기반 타입·MISRA 일부 검사, 선택적 Clang-Tidy 검사를 통합합니다. Python addon을 실행하지 않습니다.
- C# 직접 MISRA 검사 25개와 9.1 매핑의 범위는 [아키텍처](02_architecture.md#c-분석기의-구현-범위)에 명시합니다. Python `misra.py` 전체와의 동등성을 보장하지 않습니다.
- 축소·부호 변환은 대입·초기화·인자 전달·반환에서 검사합니다. 명시적 캐스트가 있어도 캐스트 결과에서 최종 대상 타입까지의 암묵적 변환을 검사합니다.
- 판정 가능한 필수 타입과 상수 표현 범위를 사용합니다. 타입·AST·함수 매개변수 정보 등을 해석할 수 없으면 일부 검사를 생략할 수 있습니다.
- 등록된 477개 규칙의 한글 설명을 연결합니다. 코드 예시가 없는 항목은 미등록 안내를 표시합니다. 등록 수는 엔진이 실제로 실행·검출하는 규칙 수나 규정 준수율을 뜻하지 않습니다.
- DB 미등록 ID도 엔진 원문과 미등록 한글 안내를 표시합니다. 결과를 받으면 해당 ID를 기본 ON으로 런타임 룰셋에 추가하여 목록·요약에서 유실되지 않게 합니다. 사용자 OFF와 예외·검색·분류 필터는 그대로 적용합니다.
- 발견한 ID의 ON/OFF는 프로젝트에 저장하며, DB에 없는 저장 ID도 임시 규칙으로 복원한 뒤 재분석에 적용합니다. 실행 중 DB 파일의 자동 번역·등록은 수행하지 않습니다.

## FR-06. 룰셋과 예외

- 카테고리·ID·한글 설명으로 규칙을 찾고 ON/OFF합니다. 기본 심각도, MISRA 의무 등급, 그 외 규칙의 프로젝트 검토 정책을 구분합니다.
- 목록 전체 선택/해제는 표시 중인 규칙에 적용하고, 필수/우선 검토 선택과 형변환 집중 선택은 전체 규칙에 적용합니다.
- 개별 예외는 **규칙 ID + 파일 경로 + 줄 번호**로 식별합니다. 같은 규칙이 같은 줄의 여러 열에서 검출되면 함께 예외 처리됩니다. 열 단위 예외 기능은 없습니다.
- 줄 전체 예외는 해당 줄의 진단에 대해 각각 예외 키를 추가합니다. 예외 복원과 규칙 전체 OFF도 지원합니다.

## FR-07. 결과 목록과 규칙별 요약

- 결과 영역은 결함 목록, 규칙별 요약, 노트, 예외 항목의 네 탭입니다.
- 결함 목록과 규칙별 요약은 검색어·분류·ON/OFF·예외 상태를 공유합니다.
- 규칙별 요약은 발생 건수 내림차순, 동률이면 규칙 ID 순으로 표시합니다. 건수는 줄 수가 아니라 진단 항목 수입니다.
- 그룹을 펼치면 파일 경로·줄·열과 현재 파일에서 읽은 코드 한 줄을 표시합니다. 항목을 선택하면 해당 진단의 상세 설명과 코드 줄로 이동합니다.
- 파일이 없거나 줄이 변경된 경우 안내를 표시합니다. 요약의 코드 미리보기는 분석 당시의 저장 스냅샷이 아닙니다.

## FR-08. 프로젝트·외부 도구·취소

- `*.jcproj`에 대상/참조 경로, 제외 경로, 타겟, C 표준, 매크로·엔진 옵션, 룰셋, 예외 목록을 저장하고 복원합니다. 분석 결과·검색어·요약 접기 상태는 파일에 저장하지 않습니다.
- VS Code가 설치되어 있으면 선택한 줄을 열고, 없거나 실행에 실패하면 메모장으로 파일을 엽니다. 메모장에서는 줄 이동을 보장하지 않습니다.
- 실행 중 취소 시 분석 도구 프로세스를 종료하고 이번 실행의 dump 등 임시 산출물을 정리합니다. 기존 dump는 백업 후 복원하며, 복원에 실패한 백업은 수동 복구를 위해 남을 수 있습니다.
- 샘플 자동 로드/수동 로드 및 프로그램 정보 창을 제공합니다.

## 비기능 요구사항과 제외 범위

- WPF·내장 분석 도구 실행 플랫폼은 Windows입니다. Linux에서는 교차 빌드와 WPF 없는 콘솔 회귀 테스트를 사용합니다.
- 타겟과 한글 설명은 JSON/XML로 분리하고, 프로그램 로드 시 읽습니다. 편집 후 실행 중 목록에 자동 반영되는 기능은 없습니다.
- 소스 분석은 읽기 중심이지만 Cppcheck dump는 소스 옆에 생성되므로 쓰기 권한이 필요합니다.
- PDF/Word/HTML/Excel 등 외부 제출용 보고서 생성은 제외 범위입니다.

## 남은 구현 불일치와 검증 제한

- **부분 구현 범위:** MISRA 10.x/11.x 전체, 단일 반환 규칙 15.5 등은 구현 완료로 간주하지 않습니다. 일부 규칙은 타입·상수·스코프 정보가 있는 사례만 검사합니다.
- **검증 범위:** 콘솔 회귀 테스트는 합성 AST, dump XML, 메시지 처리 및 ViewModel 상태를 검증합니다. Windows GUI 조작, 내장 실행 파일과 실제 소스의 전체 통합 비교, Python addon과의 전체 동등성 검증은 포함하지 않습니다.
