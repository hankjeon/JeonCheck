# 01. 요구사항 및 기능 명세서 (Requirements Specification)

## 1. 개요 및 목적
- **프로젝트명**: **전검사** (`JeonCheck`)
- **목적**: 고신뢰성이 요구되는 임베디드 시스템용 C 언어 소스 코드에 대해, 복잡한 컴파일러 환경 구성 없이도 정적 결함(메모리 오류, 암묵적 축소 변환, MISRA C 2012 위반 등)을 검출하고 코드 라인별 검사 범위를 직관적으로 확인할 수 있는 Windows 데스크탑 도구(.NET 10 WPF)를 개발한다.

---

## 2. 핵심 요구사항 (Functional Requirements)

### FR-01. 소스 코드 임포트 및 대상/비대상 분리
1. 사용자는 **폴더 단위** 또는 **개별 파일(`.c`, `.h`) 단위**로 소스 코드를 프로젝트에 추가할 수 있어야 한다.
2. 추가된 폴더 및 파일 트리에서 각 항목을 **검사 대상(Target)**과 **비대상(Non-Target / 참조·제외)**으로 체크박스를 통해 분리 설정할 수 있어야 한다.
   - **검사 대상 파일**: Cppcheck 및 AST 분석을 직접 수행하여 결함 및 라인 상태를 도출하는 파일
   - **비대상 파일**: 직접 결함 리포트 대상에서는 제외하되, 헤더 참조(`-I` 경로 자동 등록)용으로만 사용하거나 분석에서 제외(`-i`)하는 파일

### FR-02. 컴파일러 비종속 타겟 프리셋 설정
1. 별도의 크로스 컴파일러 설치나 빌드 스크립트 연동 없이, 드롭다운에서 **임베디드 타겟 프리셋**만 선택하여 분석을 수행할 수 있어야 한다.
2. 기본 내장 타겟 프리셋:
   - **TI DSP (COFF 40-bit long)**: `TMS320C6746`, `TMS320C6655`, `TMS320C6672`, `TMS320C6678`
   - **TI DSP (EABI 32-bit long)**: `TMS320C6746`, `TMS320C6655`, `TMS320C6672`, `TMS320C6678`
   - **NXP**: `QorIQ T1024` (PowerPC e5500, Big Endian)
   - **Microchip**: `PolarFire SoC` (64-bit RISC-V, Little Endian)
   - **AMD/Xilinx**: `Versal AP` (ARM Cortex-A72, 64-bit Little Endian)
   - **AMD/Xilinx**: `Versal RP` (ARM Cortex-R5F, 32-bit Little Endian)
3. 각 프리셋은 타겟의 비트 수, 기본 자료형 크기(`sizeof`), 엔디안(Big/Little) 및 컴파일러 고유 키워드(예: TI DSP의 `cregister`, `interrupt`, `far`, `near` 등) 치환 매크로를 자동 적용해야 한다.

### FR-03. 불완전한 환경에서의 유연한 분석 및 누락 파일 분리 표시
1. 외부 라이브러리 헤더나 일부 `#include` 파일이 누락되어 있더라도 구문 분석을 중단하지 않고 가능한 범위까지 최대한 분석을 수행해야 한다.
2. 포함 파일 누락(`missingInclude`, `missingIncludeSystem`)이나 매크로 미정의로 인해 분석하지 못한 사항은 일반 코드 결함(Error/Warning)과 섞이지 않도록 별도의 **[노트 / 안내 (Info & Notes)]** 탭으로 분리하여 표시해야 한다.

### FR-04. 코드 뷰어 및 라인별 검사/미검사 시각화
1. 파일 트리에서 C/H 파일을 선택하면 내장 코드 뷰어에서 줄 번호와 함께 소스 코드를 표시한다.
2. 검사 대상 파일의 각 라인에 대해 Cppcheck `--dump` 토큰/전처리 결과를 기반으로 다음 3가지 상태를 시각적으로 구분 표시한다:
   - **검사 완료 라인 (Analyzed)**: 전처리기를 통과하여 실제 정적 분석 및 AST 검사가 수행된 유효 코드 줄
   - **미검사 라인 (Skipped)**: `#ifdef` / `#if` 조건 불충족 등으로 전처리 단계에서 제외되어 분석기가 검사하지 못한 코드 줄 (주석 및 단순 공백 줄과 구분)
   - **결함 검출 라인 (Defect)**: 선택된 룰셋에 의해 결함이나 규칙 위반이 검출된 줄 (심각도에 따른 강조 표시)

### FR-05. 암묵적 축소 변환, MISRA C 2012 및 Clang-Tidy (CERT-C) 통합 검출
1. Python 의존성 없이 `.dump` AST 및 `ValueType` 정보를 C# 네이티브 분석기로 정밀 검사한다.
2. **암묵적 축소 변환(`ImplicitNarrowingConversion`)** 필수 검출:
   - 대입문(`=`), 변수 선언 초기화, 함수 호출 인자 전달, `return` 문에서 명시적 캐스트 없이 더 큰 비트 폭의 정수/실수 타입이 더 작은 타입에 대입되는 경우
   - `double` → `float`, 부동소수점 → 정수형 암묵적 변환
   - 부호 있는 타입과 부호 없는 타입 간의 암묵적 변환(`ImplicitSignConversion`)
3. **MISRA C 2012 핵심 규칙**을 C# 네이티브 규칙 엔진으로 검사하고, 각 위반 항목에 대해 한글 해설과 위반/개선 코드 예시를 제공한다.
4. **Clang-Tidy (`tools/clang-tidy/`) 심층 분석 연동**:
   - 타겟 프리셋의 Clang 아키텍처 트리플(`--target=`) 및 매크로 설정과 자동 연동하여 `bugprone-*`, `cert-*`(CERT-C 보안/안전 표준), `clang-analyzer-*`(경로 민감 분석) 검사를 수행한다.
   - 누락된 `#include` 헤더가 존재할 경우 임시 더미(Stub) 헤더를 자동 생성하여 컴파일 중단 없이 끝까지 분석을 완료한다.

### FR-06. 검사 규칙(Ruleset) 선택 및 개별 예외(Suppression) 관리
1. 전체 지원 규칙 목록을 카테고리, 규칙 ID, 중요도, 한글 한 줄 요약과 함께 조회할 수 있는 **룰셋 설정 창**을 제공한다.
2. 개발자가 의도적으로 사용하는 문법이나 불필요한 규칙을 검사에서 제외(OFF)하거나 특정 규칙만 선택(ON)할 수 있어야 한다.
3. 키워드 검색 및 카테고리별 일괄 선택/해제 기능을 지원한다.
4. **개별 위치 예외(무시) 처리**: 규칙 전체를 끄지 않더라도 특정 파일·특정 라인의 결함 항목만 우클릭으로 예외(무시) 처리하거나 해제할 수 있어야 한다.

### FR-07. 조건부 컴파일(`#ifdef`) 옵션 및 외부 편집기 연동
1. 상단 툴바/설정에서 사용자 정의 매크로(`-D`, 예: `USE_DMA=1`)를 간단히 추가할 수 있어야 하며, 필요 시 **`모든 #ifdef 분기 강제 검사(--force)`** 옵션을 켜고 끌 수 있어야 한다.
2. 내장 코드 뷰어는 라인 상태 시각화를 위한 읽기 전용 뷰어로 동작하며, 선택한 파일/라인을 **외부 에디터(VS Code, 메모장 등)로 열기** 및 **탐색기에서 폴더 열기** 기능을 제공한다.

### FR-08. 프로젝트 저장 및 불러오기 (`*.jcproj`)
1. 현재 작업 중인 프로젝트의 **임포트된 폴더/파일 목록, 검사 대상/비대상 체크 상태, 선택된 타겟 프리셋, 매크로/`--force` 옵션, 룰셋 ON/OFF 상태, 개별 줄 예외 처리 목록**을 단일 프로젝트 파일(`*.jcproj`)로 저장하고 다시 불러올 수 있어야 한다.

## 3. 비기능 요구사항 및 제외 범위

- **개발 및 실행 환경**: Windows 10/11 (x64), .NET 10.0 WPF
- **포터블 실행**: `tools/cppcheck/` 폴더에 Cppcheck 실행 환경을 내장하며, 별도의 Python 설치를 요구하지 않는다.
- **데이터 외부화**: 타겟 프리셋(`data/targets/`)과 한글 규칙 해설(`data/rules_ko.json`)은 JSON/XML 파일로 분리하여 코드 재컴파일 없이 수정·확장 가능하게 한다.
- **제외 범위 (Out of Scope)**:
  - 외부 제출용 리포트 문서 생성 기능(PDF, Word, HTML, Excel 출력 등)은 현 단계에서 구현하지 않는다.
