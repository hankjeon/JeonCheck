# 04. 화면 구성 및 UX 설계서 (UI & UX Design)

## 1. 테마 및 폰트 디자인 가이드 (Dark Theme & Monospace Font)

- **컬러 테마**: 장시간 코드 검토 시 눈의 피로를 줄이는 **VS Code 스타일 모던 다크 테마 (Dark Mode)** 적용
  - 기본 배경: `#1E1E1E` (코드 뷰어), `#252526` (사이드 패널 및 목록), `#2D2D30` (툴바 및 헤더)
  - 라인 상태 색상 (다크 테마 최적화):
    - 🟢 **검사 완료 줄 (Analyzed)**: 좌측 `#2EA043` 상태바 + `#12261E` 은은한 녹색 틴트 배경
    - ⚪ **미검사 줄 (Skipped)**: 좌측 `#6E7681` 점선 상태바 + `#161616` 어두운 배경 + `#6E7681` 흐린 이탤릭 텍스트
    - 🔴 **결함 검출 줄 (Defect)**: 좌측 `#F85149` (오류) / `#D29922` (경고) 상태바 + `#3D1D20` / `#382A14` 강조 배경
- **코딩 폰트**:
  - 코드 뷰어 및 코드 예시 영역에는 가독성이 검증된 오픈소스 개발자용 고정폭(Monospace) 글꼴(`JetBrains Mono` / `D2Coding` 내장 포함, 폴백 `Cascadia Mono, Consolas`)을 적용하여 영문/숫자/기호(`0` vs `O`, `1` vs `l` vs `I`) 및 한글 주석의 정렬과 가독성을 보장한다.

## 2. 메인 윈도우 (`MainWindow`) 레이아웃

개발자가 검사 대상/비대상 파일 트리, 코드 라인별 검사 상태, 검출된 결함 목록, 그리고 한글 상세 해설을 한 화면에서 끊김 없이 확인할 수 있도록 **상단 툴바 + 3열(좌측 상하분리 / 중앙 상하분리 / 우측 상세해설) 레이아웃**으로 구성한다.

```text
+---------------------------------------------------------------------------------------------------+
| [새 프로젝트] [열기] [저장] | 타겟: [TI DSP C6678 (EABI) v] [-D 매크로] [x]모든분기 | [규칙 설정] [▶ 분석] |
+---------------------------+-------------------------------------------+---------------------------+
| 🟢 검사 대상 코드 (Target)  | 📄 control_loop.c  [■검사됨 ■미검사 ■결함]  | 📖 결함 및 규칙 상세 해설     |
| [+폴더] [+파일] [-제거]     |-------------------------------------------|---------------------------|
| 📁 src                    |   1 | #include "dsp_types.h"              | [규칙 ID]                  |
|   ├── 📄 main.c     (🔴2) | 🟢2 | int16_t calc_torque(int32_t input)  | implicitNarrowing         |
|   └── 📄 control.c  (🔴1) | 🟢3 | {                                   | (MISRA C 2012 Rule 10.3)  |
|---------------------------| 🔴4 |     int16_t out = input;            |                           |
|  [▼ 비대상으로 제외]        | ⚪5 | #ifdef DEBUG_SIMULATION             | [상세 설명]                |
|  [▲ 검사 대상으로 포함]     | ⚪6 |     log_debug(out);                 | 32-bit('int32_t') 수식이   |
|---------------------------| ⚪7 | #endif                              | 명시적 캐스트 없이 더 작은   |
| ⚪ 비대상/참조 코드         | 🟢8 |     return out;                     | 16-bit('int16_t') 변수에   |
| [+폴더] [+파일] [-제거]     | 🟢9 | }                                   | 대입되었습니다...            |
| 📁 bsp_driver (헤더 참조용) +-------------------------------------------+                           |
|   ├── 📄 csl_timer.h      | [결함 및 규칙 위반 (12)] [노트/안내 (2)] [예외] | [위반 예시 (Bad)]          |
|   └── 📄 csl_timer.c      |-------------------------------------------| int16_t a = int32_val;    |
|                           | 중요도 | 규칙 ID          | 파일    | 라인 | 설명|                           |
|                           | 경  고 | implicitNarrow..| control.| 4   | ... | [개선 예시 (Good)]         |
|                           | 오  류 | arrayIndexOut.. | main.c  | 42  | ... | int16_t a = (int16_t)...  |
+---------------------------+-------------------------------------------+---------------------------+
| 상태바: 준비 완료 | 검사 대상: 2개 파일 (비대상/참조: 2개) | 활성 규칙: 68개                        |
+---------------------------------------------------------------------------------------------------+
```

## 3. 영역별 세부 기능 및 동작

### 3.1 상단 2단 툴바 (Two-tier Toolbar)
- **1단 (프로젝트 및 실행 바)**:
  - 좌측: `[📄 새 프로젝트]`, `[📂 열기(*.jcproj)]`, `[💾 저장]`, `[🧪 샘플 로드]`
  - 우측 고정: `[⚙ 검사 규칙 설정 (N/M)]`, `[▶ 정적 분석 시작]` (창 크기가 작아도 우측 실행 버튼이 가려지지 않도록 고정)
- **2단 (타겟 및 분석 옵션 바)**:
  - **타겟 프리셋 드롭다운**: TI DSP (`6746`, `6655`, `6672`, `6678`), NXP `T1024`, `PolarFire SoC`, `Versal AP/RP` 즉시 선택
  - **전처리기 및 엔진 옵션**: `[C 표준]`, `[-D 매크로 입력]`, `[☑ 모든 #ifdef 분기 강제 검사]`, `[☑ Clang-Tidy (CERT-C / 심층 분석) 포함]`

### 3.2 좌측 패널: 상하 분리형 소스 트리 (상단: 검사 대상 / 하단: 비대상·참조)
- **상단 영역 (`🟢 검사 대상 코드`)**:
  - 전용 `[+폴더]`, `[+파일]`, `[-제거]` 버튼 제공
  - 폴더/파일 트리 형태로 표시하며, 여기에 속한 파일들만 정적 분석을 수행하고 파일명 우측에 검출된 결함 수 배지(`🔴 12`)를 표시
- **중앙 전환 버튼 (`▼` / `▲`)**:
  - 상단 트리에서 특정 하위 폴더나 파일을 선택하고 **`[▼ 비대상으로 제외]`** 클릭 시 하단 비대상 목록으로 즉시 이동
  - 하단 트리에서 항목을 선택하고 **`[▲ 검사 대상으로 포함]`** 클릭 시 상단 검사 대상 목록으로 이동
- **하단 영역 (`⚪ 비대상 / 참조 코드`)**:
  - 전용 `[+폴더]`, `[+파일]`, `[-제거]` 버튼 제공
  - 직접 결함 검사는 수행하지 않되, 폴더 경로는 Cppcheck 및 Clang-Tidy의 헤더 검색 경로(`-I`)로 자동 등록되어 검사 대상 코드의 `#include` 참조를 지원함

### 3.3 중앙 상단 패널: 라인 상태 시각화 코드 뷰어 및 줄 단위 예외/복원
- 각 코드 라인의 좌측 컬러 상태바, 상태 도트(Dot), 배경색 및 우측 인라인 배지로 상태를 구분:
  - 🟢 **검사 완료 줄 (`Analyzed`)**: 초록색 상태바 + 초록 도트 + 은은한 녹색 배경
  - ⚪ **미검사 줄 (`Skipped`)**: 회색 상태바 + 회색 이탤릭 텍스트 + `[미검사]` 배지
  - 🔴/🟠 **결함 검출 줄 (`Error` / `Warning`)**: 빨간색/주황색 상태바 + 강조 배경 + **`[규칙ID]`** 간결 배지 + 바로 옆 **`[🔇 이 줄 예외]`** 버튼
  - 🔇 **예외 제외된 줄 (`Suppressed`)**: 보라색 상태바(`#8957E5`) + 보라빛 음영 배경(`#1F192C`) + **`[예외: 규칙ID]`** 배지 + 바로 옆 **`[↩ 다시 검사(복원)]`** 버튼 제공

### 2.3 중앙 상단 패널: 라인 상태 시각화 코드 뷰어
- 파일을 클릭하거나 하단 결함 목록을 클릭하면 해당 소스 파일을 로드하고 해당 라인으로 자동 스크롤
- 각 코드 라인의 좌측 마진 및 배경색으로 상태를 명확히 구분:
  - 🟢 **검사 완료 줄 (Analyzed)**: 연한 녹색 좌측 상태바 + 은은한 녹색 배경 틴트 (실제 분석기가 토큰 및 타입 검사를 완료한 코드 라인)
  - ⚪ **미검사 줄 (Skipped)**: 회색/점선 상태바 + 흐린 회색 이탤릭 텍스트 및 `[미검사(전처리 제외)]` 표시 (`#ifdef` 불충족 등으로 건너뛴 코드 라인)
  - 🔴/🟠 **결함 검출 줄 (Defect)**: 빨간색/주황색 상태바 + 강조 배경색 및 해당 줄에 검출된 결함 메시지 인라인/툴팁 표시
  - **일반 줄 (주석/공백/전처리 지시문)**: 기본 배경 유지
- 상단에 **검사 통계 요약 배지** 표시: `총 120줄 | 실제 코드 85줄 | 검사 완료 78줄 (91.8%) | 미검사 7줄 | 결함 3건`
- 우측 상단(또는 우클릭 메뉴)에 **`[외부 편집기(VS Code/메모장)로 열기]`**, **`[폴더 열기]`** 버튼 제공

### 2.4 중앙 하단 패널: 결과 탭 (결함 목록 vs 노트/누락 파일 분리 vs 예외 목록)
1. **탭 1 - `[결함 및 규칙 위반 (N)]`**:
   - 컬럼: `심각도`, `분류`, `규칙 ID`, `파일명`, `라인`, `검출 메시지(한글 요약)`
   - 항목 클릭 시: 중앙 코드 뷰어가 해당 파일의 해당 라인으로 즉시 이동하고, 우측 패널에 해당 규칙의 상세 한글 해설 표시
   - 항목 우클릭 컨텍스트 메뉴:
     - **`[이 위치(파일:라인)의 결함만 예외(무시) 처리]`** (프로젝트의 예외 목록으로 이동)
     - **`[이 규칙(ID) 전체를 현재 프로젝트 검사에서 제외]`** (즉시 해당 규칙 OFF 반영)
2. **탭 2 - `[노트 / 분석 참고 안내 (M)]`**:
   - 누락된 포함 파일(`missingInclude`: 예: `"ti/csl/csl_chip.h" 파일을 찾을 수 없어 일부 매크로가 기본값으로 처리됨`) 및 분석 환경 안내 메시지를 별도로 모아 표시하여 실제 코드 결함과 혼동되지 않도록 분리
3. **탭 3 - `[예외(무시) 처리된 항목 (K)]`**:
   - 사용자가 개별 예외 처리한 항목을 확인하고 언제든 **`[예외 해제(복원)]`** 할 수 있는 목록 제공

### 2.5 우측 패널: 결함 및 규칙 상세 한글 해설 뷰
- 선택된 결함 항목에 대해 `rules_ko.json`의 풍부한 해설 데이터를 표시:
  - **규칙 ID 및 타이틀** (예: `implicitNarrowing` / `misra-c2012-10.3`)
  - **중요도 및 의무 등급** (`필수 Required`, `권고 Advisory` 등)
  - **실제 검출 상세 내역** (예: `우변 'input' (int32_t, 32-bit) -> 좌변 'out' (int16_t, 16-bit)`)
  - **왜 위험한가 (상세 설명)**: 임베디드 환경에서의 잠재적 위험성 한글 해설
  - **위반 코드 예시 (Bad Code)** & **권장 수정 예시 (Good Code)** 박스

## 3. 검사 규칙 설정 창 (`RulesetWindow`) 구성

- **상단 필터 바**:
  - 카테고리 필터 드롭다운 (`전체`, `타입 및 형변환`, `치명적 오류`, `MISRA C 2012`, `포인터 및 메모리`, `제어 흐름` 등)
  - 키워드 검색창 (규칙 ID, 한글 제목, 설명 내 단어 실시간 검색)
  - 빠른 선택 버튼: `[전체 선택]`, `[전체 해제]`, `[필수(Required) 규칙만 선택]`, `[형변환/타입 안전성만 선택]`
- **중앙 규칙 목록 (DataGrid)**:
  - `[☑ 활성]`, `[규칙 ID]`, `[분류]`, `[등급]`, `[한글 한 줄 요약]`
- **하단 상세 미리보기**:
  - 목록에서 선택한 규칙의 상세 설명과 Bad/Good 예시를 창 하단에서 바로 확인하고 켤지 끌지 결정 가능
- **하단 버튼**: `[적용 및 닫기]`, `[취소]`
