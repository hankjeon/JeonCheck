# 05. 추가 기능 구현 계획

## 목적과 상태

논의한 추가 기능을 향후 구현 대상으로 식별한다. 아래 항목은 **계획 단계이며 미구현**이다. 이 문서에 기록하는 것은 구현 시작 지시를 의미하지 않으며, 구체적인 설계와 구현은 별도 요청 시 진행한다.

기본 대상은 .NET WPF 앱(`dotnetapp/`)이다. Python 앱(`pyapp/`)의 분석·수정은 별도 요청이 있을 때만 진행한다.

## PLAN-01. 프로젝트 전체 문구 검색

**상태:** 구현 대상 식별 완료 / 상세 설계 대기

### 정리된 요구사항

- 프로젝트 파일의 내용에서 문구를 찾는다. 기존 결함 목록의 검색·분류 필터와 별개의 기능이다.
- 검색 범위를 사용자가 선택할 수 있게 한다.
- 일반 문자열 검색과 정규식 검색을 지원한다.
- 대소문자 구분 여부와 단어 일부 일치·단어 전체 일치 옵션을 제공한다.
- 결과는 파일별로 묶어 파일 경로, 줄 번호, 해당 줄 내용을 표시한다.
- 결과 선택 시 코드 뷰어의 해당 위치로 이동하고 검색어를 강조한다.
- 잘못된 정규식을 입력하면 사용자에게 오류를 안내한다.

### 구현 전에 확정할 사항

- 검색 범위 선택 항목과 기본값: 전체 프로젝트, 대상 파일, 참조 파일, 선택한 파일·폴더 등의 구체적인 구성과 제외 파일 포함 여부.
- 단어 경계의 정의: 밑줄·숫자·한글 등을 포함하는 식별자 처리와 정규식 사용 시 단어 전체 일치 옵션의 조합.
- 검색 결과 화면의 위치, 대용량 검색의 취소·응답성, 읽을 수 없는 파일 및 인코딩 처리.

### 구현 시 검증 기준

- 선택한 범위에 속한 파일만 검색되며, 문자열·정규식·대소문자·단어 일치 옵션에 따라 결과가 달라지는지 확인한다.
- 결과의 파일·줄·강조 위치가 실제 내용과 일치하고 잘못된 정규식이 앱 종료로 이어지지 않는지 확인한다.

## PLAN-02. 버전별 변경 이력의 JSON 분리

**상태:** 구현 대상 식별 완료 / 상세 설계 대기

### 정리된 요구사항

- 버전별 변경 이력을 코드에 하드코딩하는 기존 방식을 데이터 파일을 읽는 방식으로 변경한다.
- 파일 경로는 용도가 명확한 **`data/version_history.json`**으로 정한다.
- 버전, 출시일, 변경 항목을 저장하고 프로그램의 버전 히스토리 화면에서 읽어 표시한다.
- 파일 누락·형식 오류가 있어도 앱은 실행되며, 이력을 불러오지 못했다는 안내를 표시한다.
- 현재 기록된 이력을 새 데이터 파일로 이관한다.

### 구현 전에 확정할 사항

- JSON 필드명·구조, 표시 순서와 날짜 형식.
- 앱 버전 표시와 변경 이력 데이터 사이의 관계, 파일을 읽는 시점과 배포 시 포함 방식.

### 구현 시 검증 기준

- 기존 이력이 누락 없이 표시되고, JSON 변경 내용이 정한 로드 시점에 반영되는지 확인한다.
- 누락·잘못된 JSON 처리와 배포 출력에서의 파일 탐색을 확인한다.

## 진행 원칙

- 구현 요청 전에는 애플리케이션 코드나 실제 이력 JSON 파일을 만들거나 수정하지 않는다.
- 각 항목의 설계가 확정되면 관련 요구사항·UI·데이터 명세 문서를 갱신하고 구현 및 검증 결과를 별도로 기록한다.
