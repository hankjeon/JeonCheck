# 05. 추가 기능 구현 계획

## 목적과 상태

논의한 추가 기능의 계획과 구현 상태를 구분한다. PLAN-01(문구 검색)과 PLAN-02(버전 이력 JSON 분리)는 사용자 승인 후 **v1.2.0에 구현**했다. 새 계획을 문서에 기록하는 것만으로 구현 시작 지시를 받은 것으로 간주하지 않는다.

기본 대상은 .NET WPF 앱(`dotnetapp/`)이다. Python 앱(`pyapp/`)의 분석·수정은 별도 요청이 있을 때만 진행한다.

## PLAN-01. 프로젝트 전체 문구 검색

**상태:** v1.2.0 구현 / 빌드·검색 회귀 테스트 및 Windows 기본 UI 흐름 확인

### 정리된 요구사항

- 프로젝트 파일의 내용에서 문구를 찾는다. 기존 결함 목록의 검색·분류 필터와 별개의 기능이다.
- 검색 범위를 사용자가 선택할 수 있게 한다.
- 일반 문자열 검색과 정규식 검색을 지원한다.
- 대소문자 구분 여부와 단어 일부 일치·단어 전체 일치 옵션을 제공한다.
- 결과는 파일별로 묶어 파일 경로, 줄 번호, 해당 줄 내용을 표시한다.
- 결과 선택 시 코드 뷰어의 해당 위치로 이동하고 검색어를 강조한다.
- 잘못된 정규식을 입력하면 사용자에게 오류를 안내한다.

### 확정한 설계와 동작

- 코드 창은 읽기 전용으로 유지한다. 일반 드래그는 문자 단위, 더블 클릭은 단어 단위, 두 번째 클릭을 누른 채 드래그하면 단어 단위로 범위를 확장한다. 모두 시작한 한 줄 안에서만 선택한다.
- 선택 영역 우클릭의 `[선택한 텍스트 검색]`은 하단 `[검색]` 탭을 열고 검색어만 채운다. 이때 정규식은 해제하며, 실제 검색은 `[검색]` 버튼을 눌러 실행한다.
- 범위는 전체 프로젝트(기본값: 대상+참조), 대상 파일, 참조 파일, 현재 파일이다. 현재 트리에 있는 파일만 수집하고 중복은 제거한다. 디스크의 하위 폴더를 다시 스캔하거나 트리에서 제거한 파일을 포함하지 않는다. 선택한 폴더 범위는 이번 구현에 포함하지 않는다.
- 기본값은 일반 문자열·대소문자 미구분·부분 일치다. 단어는 밑줄 등 연결 구두점, 한글 등 문자, 십진 숫자, 결합 문자를 포함한다. 단어 전체 일치는 정규식에도 동일한 식별자 경계를 적용한다.
- 검색은 원본 파일 내용을 줄 단위로 읽는다. 인코딩 판별은 코드 뷰어와 공유하며, 현재 파일에서 고정한 인코딩은 검색에도 적용한다. 읽기 실패는 파일별 안내 후 나머지 파일을 계속 검색한다.
- 백그라운드 검색과 취소를 지원한다. 정규식 일치에는 250ms 제한을 적용하며 시간 초과 시 검색 중단을 안내한다. 길이 0인 정규식 일치와 여러 줄 검색은 지원하지 않는다. 파일 읽기·디코딩 자체의 중간 취소나 초대형 파일의 메모리 사용량 상한은 보장하지 않는다.
- 결과는 파일 경로별로 묶어 줄·열·해당 줄 내용을 표시한다. 선택하면 해당 줄로 이동하고 일치 부분을 강조하며, Prettify의 들여쓰기·탭 변경을 화면 위치에 반영한다. 화면 정리로 사라진 공백에는 강조할 문자가 없다.
- 검색 후 결과 줄의 내용이 달라지거나 파일을 읽을 수 없으면 안내하고 잘못된 위치로 이동하지 않는다. 검색어·옵션·결과는 `.jcproj`에 저장하지 않는다.

### 구현 시 검증 기준

- 선택한 범위에 속한 파일만 검색되며, 문자열·정규식·대소문자·단어 일치 옵션에 따라 결과가 달라지는지 확인한다.
- 결과의 파일·줄·강조 위치가 실제 내용과 일치하고 잘못된 정규식이 앱 종료로 이어지지 않는지 확인한다.

### 구현 및 검증 결과

- 구현 위치: `Services/SourceSearch.cs`, `Services/CodeTextSelection.cs`, `ViewModels/MainViewModel.Search.cs`, `Views/SelectableCodeTextBlock.cs`, `MainWindow.xaml` 및 코드비하인드.
- Windows .NET 빌드: 경고·오류 0개. `publish/` 배포 빌드는 수행하지 않았다.
- 신규 콘솔 회귀 테스트 9개 통과: 선택 경계·양방향 단어 확장, 범위·중복·제거, 검색 옵션, 인코딩·위치·읽기 실패, 정규식 오류·시간 제한, 취소·프로젝트 교체, 결과 열기·변경 감지·Prettify 강조.
- 전체 콘솔 테스트: 성공 78, 실패 1. 기존 `추가 번역 규칙을 실제 파서와 UI에서 한글 설명으로 표시` 항목은 수정 전 `753b0df`에서도 동일하게 실패(성공 69, 실패 1)한다. 이번 변경에서 해당 기존 실패는 수정하지 않았다.
- 실제 Windows 창에서 샘플의 단어 더블 클릭, 한 줄 문자 드래그와 줄 경계 제한, 우클릭 메뉴, 자동 실행 없는 검색어 채우기, 버튼 검색, 결과 줄 이동·강조를 확인했다. 선택 재렌더링 후 WPF 문자 좌표 계산도 별도 확인했다.
- 더블 클릭 후 드래그의 범위 계산은 콘솔 테스트로 확인했으며 실제 마우스 연속 제스처 전체, 대규모 프로젝트 성능, 모든 기존 진단 UI·내장 분석 도구 조합의 통합 회귀까지 검증한 것은 아니다.

## PLAN-02. 버전별 변경 이력의 JSON 분리

**상태:** v1.2.0 구현 / 빌드·콘솔 회귀 및 WPF 창 생성·표시 상태 검증

### 정리된 요구사항

- 버전별 변경 이력을 코드에 하드코딩하는 기존 방식을 데이터 파일을 읽는 방식으로 변경한다.
- 파일 경로는 용도가 명확한 **`data/version_history.json`**으로 정한다.
- 버전, 출시일, 변경 항목을 저장하고 프로그램의 버전 히스토리 화면에서 읽어 표시한다.
- 파일 누락·형식 오류가 있어도 앱은 실행되며, 이력을 불러오지 못했다는 안내를 표시한다.
- 현재 기록된 이력을 새 데이터 파일로 이관한다.

### 확정한 설계와 동작

- 최상위 `versions` 배열의 각 항목에 `version`, `releaseDate`, `added`, `changed`를 저장한다. 배열 순서대로 표시하며 최신 이력을 파일 앞에 둔다.
- 출시일은 `YYYY-MM-DD` 또는 `null`이다. 기존 코드에 날짜가 없으므로 세 버전 모두 `null`로 이관하고 화면에는 `출시일 미등록`을 표시한다. 확인되지 않은 출시일을 임의로 채우지 않는다.
- 기존 v1.2.0·v1.1.0·v1.0의 변경 항목을 모두 보존하고, v1.2.0 수정 항목에 JSON 분리를 기록한다. 앱 버전은 1.2.0을 유지하며 `AppInfo.Version`이 JSON과 독립적으로 앱 버전을 표시한다.
- 이력 창을 열 때마다 `AppContext.BaseDirectory/data/version_history.json`을 읽는다. 실행 중 열린 창의 자동 갱신은 하지 않으며 창을 닫았다 열면 외부 파일의 수정 내용이 반영된다.
- 저장소 원본은 `data/version_history.json`이다. 빌드 시 실행파일 출력 폴더의 `data/`로 복사하고, 배포 항목에도 포함한다. `ExcludeFromSingleFile=true`로 설정해 단일 실행파일 배포에서도 편집 가능한 외부 JSON으로 둔다.
- 파일 누락·읽기 실패·잘못된 JSON·필수 필드/날짜 오류는 빈 목록과 한글 오류 안내로 처리한다. `versions: []`는 등록된 이력이 없다는 안내를 표시한다. 실패 시 코드 내 이력으로 대체하지 않는다.

### 구현 시 검증 기준

- 기존 이력이 누락 없이 표시되고, JSON 변경 내용이 정한 로드 시점에 반영되는지 확인한다.
- 누락·잘못된 JSON 처리와 배포 출력에서의 파일 탐색을 확인한다.

### 구현 및 검증 결과

- 구현 위치: `Services/VersionHistory.cs`, `Views/HistoryWindow.xaml` 및 코드비하인드, `data/version_history.json`, WPF 프로젝트의 파일 복사 설정. `AppInfo`에서는 하드코딩 이력을 제거했다.
- Windows .NET 빌드: 경고·오류 0개. 신규 이력 콘솔 테스트 6개 통과(이관, 순서·날짜, 재로드, 누락·잘못된 JSON·필드, 빈 목록, 출력 경로).
- 전체 콘솔 테스트: 성공 84, 실패 1. 기존 한글 설명 테스트의 동일한 실패는 PLAN-01에 기록한 수정 전 재현 결과와 같다.
- 별도 Windows WPF 검증에서 이력 창 생성·레이아웃·바인딩을 평가해 정상 목록, 파일 누락·JSON 오류 안내, 수정 후 재생성, 날짜 표시와 앱 버전 유지, 작업 디렉터리와 무관한 경로 사용을 확인했다. 실제 마우스 조작·화면 픽셀 비교를 수행한 것은 아니다.
- 실제 빌드 출력의 JSON을 읽었고, MSBuild `GetCopyToPublishDirectoryItems`의 `data/version_history.json` 경로와 `ExcludeFromSingleFile=true` 메타데이터를 확인했다. `publish/` 배포 빌드 및 배포 실행파일 실제 구동은 수행하지 않았다.

## 진행 원칙

- 구현 요청 전에는 애플리케이션 코드나 실제 이력 JSON 파일을 만들거나 수정하지 않는다.
- 각 항목의 설계가 확정되면 관련 요구사항·UI·데이터 명세 문서를 갱신하고 구현 및 검증 결과를 별도로 기록한다.
